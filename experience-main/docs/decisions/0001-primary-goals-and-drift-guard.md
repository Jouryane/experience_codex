# 0001 · 主目标与漂移守卫

> 状态：accepted · 2026-09-19
> 触发：router 实验（[讨论 24](../discussions/24-router-experiment-results.md)）证明
> stock Codex 上“hook 拦 + dynamic tool 执行”可行后，出现了把“外置适配器已
> 可行”误当成“内置目标已达成”的漂移风险。

## 决策

Experience 的四条主目标必须按**接管深度**理解，不能按“是否用到经验”理解：

| 目标 | 第一性含义 | 最低要求 |
|---|---|---|
| 增强 agent 记忆 | 过去的成功转移不必被模型想起，也能影响当前路径 | 世界状态或动作边界触发，不靠模型主动回忆 |
| 降低 token | 减少模型决策往返，而不是减少文件/步骤数量 | 被覆盖前缀的模型决策轮次归零或少计 |
| 加快响应 | 去掉模型推理与网络往返的墙钟时间 | 至少不增加交接回合；覆盖时直接执行 |
| 熟悉领域效率 | 已知前缀不进入模型决策，未知部分才委派 | 精确匹配 + 未知不执行 + 可回滚 |

## 漂移守卫

以下三种说法不构成主目标达成：

1. “模型主动调用了经验工具” —— 这是 explicit / pull，可审计，但决策仍在模型；
2. “hook 拦住了原生调用并指向了经验工具” —— 这是 router，可靠性成立，但模型
   仍要先提出动作；
3. “stock 上不需要 fork 就能跑” —— 这是适配器能力，不是内置执行座位。

真正的主目标证据是：**已知前缀发生时，模型决策轮次被实际移除，且结果通过
可观测判据、可回滚、可审计。**

## 机制位置

| 机制 | 移除模型提案？ | 移除执行？ | 额外交接 | 归属目标 |
|---|---|---|---|---|
| dynamic tool / pull | 否 | 调用后 | 无 | 显式记忆、审计执行 |
| hook block + route | 否 | 提案后、执行前 | 有 | 确定性使用、可靠性 |
| hook `updated_input` 改写 | 否 | 同一次调用内 | 可能无 | 熟悉领域的部分 token / 速度收益（未测） |
| pre / native dispatch gate | 是 | 是 | 零 | 记忆、token、速度、熟悉领域效率 |

## 价值公式

后续研究统一用这条式子判断优先级：

```text
目标收益 ≈ P(已知前缀发生) × N(可移除的模型决策轮次)
           − 误匹配与治理成本 − 宿主集成成本
```

- `P` 不是“经验库有多少条”，而是**任务执行过程中真正出现已知转移的频率**；
- `N` 不是文件数，也不是逻辑操作数，而是**原本无法被批处理掉的模型往返数**；
- 如果 `P` 小或 `N` 被批处理吃掉，内置执行座位的成本论证会退回可靠性、
  审计与回滚，而不是 token / 速度。

## 后果

1. `router` 是适配器证据，不是内置目标的完成态；
2. 未来的 Codex 集成请求应表述为“提供 dispatch-time execution seat”，
   而不是“允许 hook 替代结果”；
3. Experience 核心保持宿主中立；Codex 集成是 native adapter，不是把核心
   并入 Codex；
4. 在请求内置之前，先测 `updated_input` 同回合改写、`P` 和 `N` 三个变量。
