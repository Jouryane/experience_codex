# 学习与复用契约（可移植声明）

> 这不是“本项目特有的实现说明”，而是一份**可以照搬到你自己 Experience 系统的
> 契约**。我们当前的一些做法是**有限规模下的妥协**；本文明确标注“主干 / 妥协 /
> 扩展点”，方便他人取用思维、替换实现，而不必复刻我们的限制。
>
> 适用读者：想给 agent 加“经验沉淀与复用”的开发者。

## 0. 一页摘要

```text
任务 ──(L3 入口)──► 命中 ACTIVE 经验？
        │ 否
        └──► 委派给 agent 执行 ──► 事件流(trace) 实时落库
                                        │ 会话结束
                                        ▼
                             L1 学习钩子(会话结束触发)
                              必要性门 → 蒸馏 → 工具边界校验
                                        │
                                        ▼
                            候选(DRAFT/CANDIDATE)  —— 不进匹配索引
                                        │ 人工/编译器提升(L2)
                                        ▼
                             ACTIVE 经验 ──► 下次命中
```

**主干**：`trace → 候选 → 提升 → 匹配 → 执行 → 判据 → 回写`。
**妥协**（可声明、可替换）：子串匹配、单轮取尾、deterministic 蒸馏只认
`exec_command`、扁平存储、相似性只有精确签名。

## 1. 自动录入（L1）契约

### 1.1 回流一定是“系统钩子”，不是模型指令

- 学习在**会话结束**由服务端触发；模型不参与“要不要学、学什么”的决策；
- 好处：幂等、可审计、模型无法给学习下指令、失败不影响用户可见路径；
- 移植建议：把 `on_session_end(session) -> Option<RoundTrace>` 做成宿主钩子，
  不要塞进 prompt。

### 1.2 必要性门（先拒绝，再学习）

| 拒绝理由 | 含义 | 迁移时的等价判断 |
|---|---|---|
| `terminal_not_success` | 任务未成功收尾 | 只看终态，不猜 |
| `no_action_evidence` | 没有任何工具调用 | 纯聊天不产生经验 |
| `repeat_no_improvement` | 同签名已存在 | 重复不再加一条 |
| `distill_unavailable` | 无可用蒸馏器/轨迹不含可用参数 | 诚实拒绝，不编参数 |
| `tool_boundary_invalid` | 步骤工具不在词表 / 参数为空 | 工具边界必须封闭 |
| `unstable_shape` | 轨迹含一次性标识（hash/uuid） | 防止把实例固化成经验 |

### 1.3 输出形态（很重要）

- 候选的 postcondition 必须是**占位**（`candidate.pending_validation`），
  即“待验证的假设”，**不能是完成声明**；
- 候选写入门只暴露“写入候选”的能力，**没有激活权**；
- 移植建议：让写候选与提升激活走两条不同代码路径（结构性隔离，而非约定）。

## 2. 复用（匹配与触发）契约

命中不是“完美匹配”，而是**分层门控的与**：

| 层 | 判据 | 当前实现 | 可替换方向 |
|---|---|---|---|
| 工具 | `trigger.tool` 相等 | ✅ | 保持 |
| 文本 | `command_pattern` 子串 | ⚠️ 妥协（否定句会误命中） | 语义/槽位匹配 |
| 作用域 | scene/scope 可枚举 | ✅ | 层级作用域 |
| 前提 | precondition 可观测且成立 | ✅（Unknown≠True） | 更多来源族 |
| 状态 | ACTIVE 且未被衰减/禁用 | ✅ | 权重模型 |
| 结果 | 跑完仍要过判据 | ✅ | 更多谓词 |
| 冲突 | 取最优覆盖，平局不执行 | ✅ | 打分模型 |

**必须一起声明的三条语义**：

1. `Unknown ≠ False`：没有观测 ≠ 条件不成立；Unknown 一律**不执行**；
2. 命中 ≠ 完成：执行后仍然要有判据，失败要分层归因（环境 vs 语义）；
3. 重复 ≠ 更好：同签名重复到达只审计、不覆盖旧经验。

## 3. 已知妥协与扩展点（宣传点）

| 妥协 | 为什么现在这样 | 你可以怎么升级 |
|---|---|---|
| 子串匹配 | 便宜、可解释、无需模型 | 任务分段 + 槽位提取 + 向量召回（先召回后精排） |
| 只取最后一轮 | trace v1 只有轮边界 | 多轮聚合 + 任务链建模 |
| deterministic 只支持 `exec_command` | 缺写入参数形状 | 扩展 trace 参数捕获 |
| 扁平存储 | 单机单用户 | 树/图存储 + 作用域继承 |
| 相似性=精确签名 | 不冒自动合并的风险 | 结构指纹聚类 + 只读报告 + 人工确认合并 |

## 4. 移植检查清单

- [ ] 学习钩子在会话结束后触发，且失败只写审计
- [ ] 候选写入没有激活权（代码层隔离）
- [ ] 至少有一条“诚实拒绝”的理由表，并且真的会拒绝
- [ ] `Unknown / False / True` 三值语义在匹配与判据上都成立
- [ ] 执行前后各有一次可观测性检查（前提 / 结论）
- [ ] 有回滚（备份 manifest）与撤销入口
- [ ] 有“一次性实例”拒绝规则（hash/uuid/时间戳）
- [ ] 相似经验有**只读**视图，再谈自动合并
