# 02 · 表示、调修与属性模型

## 一、路径 vs 叶子：这是表示层问题（C15–C19）

**C15｜我们存错了粒度。** 经验的结果是“一片树叶”，
而我们留存的是“这片叶子与树根之间的路径”（子枝 a → 母枝 b → 主干 c → 树干 D）。
可复用的资产是**段**，不是路径；同一根主干在成千上万条经验里是同一批东西，
却被复制了成千上万份。于是“近似”看起来像经验的属性，
实际上是**存储粒度造出来的假象**。

**C16｜百万级的真问题不是检索，是决策退化。**
当前 Select Plan 的规则是“取覆盖最大，平局不执行”。它的推论是：
经验越多 → 近似经验越多 → 越容易平局 → 越容易拒绝执行 →
**学习越久越退化为纯委派**。这不是内存或延迟问题；
它意味着学习闭环在规模维度上会自己把自己关掉。

**C17｜三层改造。**

| 层 | 现在 | 改成 |
|---|---|---|
| 存储 | 路径（树） | 段，内容寻址，结构是 DAG；管理界面上的树是**视图** |
| 决策 | 选一条完整经验 | **最深的已验证共同前缀** + 前沿处暴露候选后继 |
| 语义 | 无身份 | 段要有身份/签名，否则“这是同一段”不可判定 |

**C18｜三条代价（必须摆在桌上）。**

1. **验证面从任务级下沉到段级**，而且要验证**中间状态**——比验证终态难得多。
   这是“路径粒度”这个限制当初存在的真实理由，不是无理由的保守。
2. **段凭什么进入共同前缀：必须由状态决定，不能由文本决定。**
   错误的前缀会在错误的任务上被机械执行，而前缀正是副作用发生的地方。
   只有“这一段的前提被观测证实”才允许它进共同路径。
3. **段级幂等与可逆**是段合并的前提。主干段在两条不同任务上都正确执行，
   靠的正是它在两边状态里都是正确且幂等的操作——“状态可达”本身就是它该执行的证据。

**C19｜三条收益。**

1. **近似经验不再需要合并，只需要暴露分叉。** 这绕开了我们一直刻意回避的
   危险操作（“相似度=精确签名，不冒自动合并的风险”）：不需要在近似经验之间做选择，
   只需要把分叉点暴露出来。合并压力只落在主干上。
2. **“先动手 / 委派”的分界线由证据厚度决定**，而不是人工拍定整条 workflow。
   前沿就是共性验证结束的地方。
3. **参考注入从“文本希望”升级为“前沿处的分支菜单”**：
   “已知的下一步有 N 条，你选一条或另做别的”。
   这解决了文档里“先动手优先 vs 参考注入是第二位”的张力——
   注入不再是竞争者，它长在“先动手”的尽头。

> 说明：上述是**规划与讨论**，不是即刻实现项。demo 阶段有意忽略了这个规模问题，
> 这是个明确记录在案的取舍。

## 二、调修三分规则（C20–C23）

判据只有一个：**前提是否被观测证实**。

| 情形 | 判据 | 正确反应 |
|---|---|---|
| 前提**不成立** | 未观测 / 观测为假 | **收窄适用域**，不降置信度 |
| 前提成立、转移**失败** | 状态对得上，结果对不上 | **降该段的效度**，登记反例；主干分开结算 |
| 前提成立、结果只能判 **partial** | 状态对得上，结论不可判定 | **这里应该分叉** |

**C21｜partial 不是“经验不好”的信号，是“这个位置应该长出子经验”的信号。**
现在 `partial → misfire → 降 confidence` 这条链路把**结构信息**当成**质量信息**扔掉了。

**C22｜长出子经验的默认机制（自动，不需要人）：**
主干后置验证为真，且 agent 在前沿之外的续跑**本身也是可验证且成功的**——
那么那条续跑轨迹就是新的子段，它的前提就是前沿状态。

**C23｜怀疑与真正否定。**

- **怀疑**：agent 不得不**绕过或撤销**主干上的某一段。这不是段执行失败，
  而是**前提比你以为的窄**。反应是收窄适用域，不是降分。
- **真正否定**：只有“前提已被证实且稳定，转移仍然不成立”才配降一段的效度；
  即便如此也不删经验，而是登记反例。**降的是那一段，主干独立结算。**

结论：“长 / 疑 / 否”不需要人判断，它是**同一份证据的三种投影**。

## 三、轻核心与涌现属性（C24–C27）

**C24｜核心保持最小。** 执行与验证必需的最小集：
身份 / 签名、前提、转移、后置、证据。其余一律不做字段。

**C25｜特别属性一律是证据日志上的“投影”，不是“列”。**
可以缺席、可以重算、永远不会阻塞执行。

- 否定面 = 反例证据的投影
- 代价 = 时长 / 开销证据的投影
- 适用域 = 成功运行的环境指纹投影（这是“经验为什么会过期”的结构化答案，
  替代“衰减”这个统计答案）
- 守卫 vs 假设 = 前提的分类标签，也在投影上
- **类型签名是唯一需要成为列的一项**，因为它支撑静态组合；
  但它可以从转移**推导**，且允许缺席——缺席即“不可组合”，仍然可用。

**C26｜“涌理论”：少固有属性，承认涌现属性，并据涌现属性提供检索 / 选用 / 修订方案。**
工程后果是具体的：**涌现属性的演进不需要数据迁移**——改的是投影的定义，
重算即可。这是“承认涌现属性”之所以便宜的原因。
配套纪律：涌现属性必须是**可争辩**的（用户可否决排序而不改证据），
这与既有的“用户偏好是 additive 元数据、不改证据”同源。

**C27｜唯一的红线：涌现属性可以影响“选择先后”，不能影响“能不能执行”。**
（等价于既有红线：召回可以近似，执行决定必须确定性、可复现、可审计。）
这也是 C13 里“无身份标签只能排序、不能启用”的同一条规则。

## 四、置信度、适用域与回灌语义（C28–C29）

**C28｜置信度与适用域必须拆成两个对象、两个计数器。**

| | 触发条件 | 变化 |
|---|---|---|
| 置信度 | 前提**已验证**、转移失败 | 下降 |
| 适用域 | 前提被观测为**假** | 收窄（或按反向证据放宽） |

现在的实现把两者合并成一个标量，所以“前提不成立不扣经验的分”只能写成特例逻辑。
拆开之后，这条声明**从约定变成结构**。

**C29｜回灌语义的角色定位：小模型是候选生成器，不是控制器。**
与 L1 “写候选没有激活权”完全同构：

- **确定性部分（不用模型）**：失败事实落在谓词注册表内时，
  该怪哪条前提是算术，直接算。这一块覆盖大多数。
- **模型部分（小模型）**：只在失败**无法用现有谓词解释**时介入，
  任务是**提出一条缺失的前提**（“这条经验需要一条我们还没有的判据”），
  然后走与候选经验完全相同的验证门——独立检查观测证据是否真的支持“该前提为假”。

这样经验本体仍是确定性产物，只有它的**注解**来自模型；
可复现与可审计两条不被破坏。反之，若放任模型直接改写适用域，
经验的效度就变成模型的函数——等于把一个 3.5 层的东西重新降回 2 层。

## 五、原划分的降级（C43）

原有的 **State / Experience content / Runtime** 三分是**硬性分区**
（不同的 store 与不同的代码路径）。在段图里，这三者仍然存在，
但降级为**投影 / 宏观分类**，不再是硬性指标：

| 原划分 | 在段图里的角色 |
|---|---|
| State | 节点的**事实面**（前提与后置读的就是它） |
| Experience content | 边本身（前提 → 动作 → 后置） |
| Runtime | 边的**遍历**（执行过程本身也是一串段） |

**C43｜同一个段在不同观察角度下扮演不同角色，"分区"变成"投影"。**
这是 C25（投影而非列）在更高一层的同一条规则。

代价要说清：分区被降级之后，**边界无法再靠存储位置来保证**，
只能由**证据与来源**来保证——一个节点算不算“状态”，
取决于有没有判据能读它，而不取决于它被存在哪里。

**C43 附｜三种情形的统一。** “具体问题用哪些段 / 某类问题用哪些段再交给 agent 补足 /
没有对应段时让 agent 补足段”这三种情形**不是三种模式**，
而是**同一次遍历在“已知前缀长度”上的三个区段**：

| 已知前缀长度 | 情形 | 行为 |
|---|---|---|
| = 全长 | 具体问题 | 全机械执行 |
| 0 < p < 全长 | 某类问题 | 执行前缀 + 前沿交接 |
| = 0 | 无对应段 | agent 自由执行，并把结果沉淀为新段 |

生长点在拓扑上是同一件事：**agent 接管的位置，就是新段的诞生位置。**

## 六、由实验确认的硬约束（C44）

> 来源：`D:\\test\\_only\\experience-segment-mode-20260916` 的实验 E6/E7。
> 这不是推理出来的，是跑出来两次的。

**C44｜一条段的前提必须被它自己的动作证伪。**

否则它在**每一层都重新命中**，重复执行直到深度上限。

| 实例 | 现象 | 修法 |
|---|---|---|
| E6 首轮 | 段 `U1`（写 selfcheck.txt）跑到 `DEPTH_CAP` | 前提加 `file.absent(selfcheck.txt)` |
| E7 首轮 | 段 `R3_lib`（写 target.txt）跑到 `DEPTH_CAP` | 前提加 `file.absent(target.txt)` |

**推论一**：每条段都需要一条 `absent` 型前提（“还没做过”）与它的后置配对。
**推论二**：这条约束解释了 `pass_count` 为什么有意义——只有能正确退出的段，
它的通过量才是可累加的。
**推论三**：`step-gate.md` §5 的“每 turn 命中数上限”只是**给建模错误打的补丁**；
正确的门是结构性的（前提自证伪），计数器只能作为保险丝保留。
