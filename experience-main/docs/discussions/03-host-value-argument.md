# 03 · 经验对宿主 harness 的价值论证

## 一、席位论：两种来源，同一个机制（C31）

成熟的 agent runtime 都有一个“**已经决定过的，不能被后续覆盖**”的座位——
不是因为它安全，而是因为它把“每轮重决”变成“一次性固定义”。

| | 固化的是谁的决定 | 理由 | 现状 |
|---|---|---|---|
| 单调 guard / 权限契约 | **人类 / 插件作者**的先前决定 | 安全与卫生 | 已实现（DSH 的 `ctx.tools.guard()`、Codex 的 hook 权限契约） |
| experience | **模型自己**的先前决定 | 效率 | 座位在，尚未被占 |

**C31｜请求宿主支持经验，不是要求它改变世界观，而是扩展一个它已经存在的机制**：
从“人类先前决定的固化”到“模型先前决定的固化”。

## 二、宿主吸收经验的六条增量（C33）

按价值从高到低。原版针对 DSH 写，这里改成任何 agent runtime 都适用的形式。

1. **宿主的确定性上限就是模型。** append-only 日志、fork、resume 提供的是**重放**，
   不是**复用**——重放会把模型当时的随机决策（含走错的那些）一起再现。
   经验提供“可复现的结果”，这是宿主自身结构达不到的天花板之上的一层。
2. **把组合做到极致，但没有“避免工作”的理论。** 每个 turn 都是一次全量推理，
   成本随工作量线性增长。对一个想做基础设施的 harness 来说，
   没有次线性路径是结构性上限。经验提供“已知工作 ≈ 0 token”。
3. **“可重建”不等于“被授权”。** 日志能告诉你发生了什么，
   不能告诉你“发生的事情在发生前是被允许的”。经验带来的正是后者：
   **副作用在发生前被授权，且留下证据。**
4. **插件生态缺一个“比插件小、比提示词可信”的分享单位。**
   用户真正想分享的东西（“在这个仓库里该怎么开工”）既不是包、也不是提示词。
   段化的经验段正好填这个空。**这也是 C15–C19 不只是技术洁癖的原因：
   整条路径的 DAG 无法被分享，成千上万个段可以。**
5. **座位比想象的便宜。** 承载条件（单调 guard、可回卷 effect、完整日志、
   无特权核心 / 或 Codex 侧的 hook + plugin + 动态工具）都已经存在，
   且占用很轻。边际成本低。
6. **根本的一条：一个模型无关的 harness，自身价值是商品化的。**
   模型无关意味着价值上限被“任何人都能插进来的最好的模型”封顶。
   一个中立的 harness 若不能自己增值，就只能是商品层；
   经验是唯一能让 harness 自身**随时间增值、且不依赖模型进步**的机制。
   所以它不是“多了一个功能”，而是**从最好的第 3 层变成占住 3.5 层**。

## 三、代价（C34）

**C34｜宿主侧要承担的是“拥有策略”，以及“两个账本”的边界问题。**

- 它原本把策略边界交给用户/模型；吸收经验后，它自己成为策略的持有者。
  有些 harness 是**刻意**规避这一点的，这是真实代价，不是技术难点。
- 更实质的是：段一旦跨会话、跨项目，会话日志就不再是唯一账本。
  见 [README 未决问题 U1](README.md#未决问题不当作结论使用)。

## 四、价值观修正（C35）

> 本条替代早前“宿主的世界观（模型做决定，插件塑造环境）与 experience 冲突”的判断。
> **那个判断是错的。**

**C35｜experience 不是“不让模型做决定”，而是“不让模型对自己已经成功做过的事
再次做重复决定”。** 这个区别是根本性的：

- experience **来自模型**——每一条路径最初都是模型自己走出来的。
  所以它不构成第二个决策者，它构成的是**已做决定的记忆**。
- 因此它的合法性来源是**模型自己**，而不是任何外部规则。
  它不该、也不能推翻模型的新判断；它只在“状态与证据都指向同一件事”时
  替模型省下一次重复推理。
- **模型是作者，经验是已验证的出版版本。** 二者不是监管关系，是同一条价值链的两端。

推论（把 C9 与 C11 统一到一个机制里）：既然经验来自模型，
那么“**模型版本**”就是经验适用域里权重最大的那一维。
模型升级时，旧模型产生的后增经验未必仍然成立——先天经验的厂商生命周期
与后增经验的个体生命周期，因此在同一个机制（适用域）下被统一。

## 五、商业论证（C36–C38）

**C36｜模型服务商不可能吞噬全部利润。**
每一层基础设施的历史都是这样分化的：算力没有吞掉操作系统与数据库的价值。
结构性理由：模型服务商的边际价值来自**通用能力**，
而利润沉淀在**特定场景的确定性**上。通用能力越强，场景确定性越值钱——
因为差距被抹平之后，剩下的竞争只剩可靠性、成本与合规。

**C37｜当前 agent 行业的两种形态，都是对中间层的逃避。**

| 形态 | 症状 | 商业缺陷 |
|---|---|---|
| 杂项扩展过多 | 每加一项能力就加插件/提示词/schema，token 消耗线性增长，且扩展的正确性无保证 | 成本失控，可靠性不可证 |
| 完全整洁 | 优雅，但依然完全依赖 LLM | 无护城河；任何模型升级都会重置竞争 |

前者把复杂度放进“扩展”，后者把复杂度放进“模型”。中间层就是 experience。

**C38｜experience 卖的是结构属性，不是能力；因此它的价值与模型能力同向。**

- 能力问题会被模型解决，**结构问题不会**：可复现、可审计、可回滚、零边际成本——
  这几条不是“模型更聪明”能提供的性质。
  这也正是 `why-3-5-layer.md` §3 已经写下的话：这四条不像 AI 能力，更像个基础设施。
- 推论：**模型越强，experience 的价值越高，而不是被替代。**
- 也是唯一**可以脱离模型版本独立定价**的资产：它的价值来自你自己的运行历史，
  不是别人的权重。用户对“自己的经验库”有迁移成本（粘性），对模型能力没有。
- 由此得到天然的三方宪法：**先天/预设经验是厂商的，后增经验是用户的，
  接口标准化且可导出**。

### 6.2 反对（必须同时说）

| # | 反论 | 结论 |
|---|---|---|
| W1 | **价值与重复度成正比** | 单用户探索型用法重复度低 → 价值真实但不大 |
| W2 | **冷启动** | 宿主不附带经验；价值需要厂商下发模板或用户累积，两者都要时间。接进去得到的是**能力**，不是**第一天就有的价值** |
| W3 | **失败是非局部且无声的** | 一个乱走的钟会污染工作而没人看管。对还在破坏性变更期的项目，加一个静默自主行为体，风险确实高于加一个工具 |
| W4 | **价值高度依赖工作负载形状** | 研究 / 一次性 → 接近 0；ops / CI / 合规 / 数据管线 → 几乎就是全部 |

### 6.3 结论

**不是“普遍巨大”，是“不对称地巨大”：在重复且可验证的工作上巨大，在探索型工作
上接近于零。**

但“时间维度”这个定义**换了买家**：它卖的不是“让 agent 更擅长重复劳动”，
而是“**让 agent 拥有过去**”。而“拥有过去”对**任何长期运行同一个 agent 的场景**
都有价值——也就是平台型 / 企业型用法，**恰好是中立 harness 想去的地方**，
因为它拼不过模型质量，只能拼别的东西。
