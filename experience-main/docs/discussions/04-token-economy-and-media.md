# 04 · 介质与成本：为什么“省 token”是判据

> 出发点不能忘：experience 的存在理由之一是**省 token**。
> 省 token 有且只有两个来源：
>
> - **A｜机械执行**：已知前缀在进程内完成，不进模型 → 零推理付费；
> - **B｜减少注入**：识别靠判定而不是靠模型挑 → 不必把候选经验塞进 prompt。
>
> 本文件用这两条去判定一切“经验该以什么形态存在”的提案。

## 一、同一角色的三种介质（C39）

“系统提示词 / RAG 知识库 / 可执行段”是**同一个角色的三种介质**——
都在回答“解决某类问题用哪些段，再与 agent 结合补足缺失”。
但它们的成本结构完全不同：

| 介质 | 表达 | 识别方式 | 成本结构 | 判定 |
|---|---|---|---|---|
| 系统提示词 | 自然语言声明 | 无（总是生效） | **每请求固定付费** | 与出发点相反 |
| RAG 知识库 | 检索片段注入 | 召回 + 模型挑选 | 按召回与注入付费，且不确定 | 半途 |
| 可执行段 | 前提 → 动作 → 后置 | 谓词判定 | **零推理付费** | 唯一符合出发点 |

**C39｜“系统提示词不就是一种先天经验与 agent 的结合吗”——是，
而且它是目前唯一被广泛使用的形态。** 它与先天经验扮演完全相同的角色，
区别只在中介：**宣示态 vs 执行态**。而两者的成本结构相反：
宣示态每请求付费，执行态零推理付费。
所以把先天经验做成提示词，不是“另一种实现”，而是**退化**。

配套结论（收口上一轮“或项”的读法）：**提示词是“与项”**（总是生效、必须遵守），
**经验是“或项”**（候选替代、可被否决）。这也是两者在语义上的分界。

## 二、小模型与 RAG 的共同缺陷（C40）

两者表面不同（把可变知识冻进不可变参数 / 把固定知识放进可检索索引），
缺陷相同：**它们把“做”变成了“查”。**

- 转移必须被**执行**；知识只能被**查阅**；
- 查阅必然发生一次请求；执行不发生请求；
- 所以凡是以“知识”形态存在的经验，都已经不在省 token 的路上。

## 三、回写代价：为什么必须 O(1)（C41）

经验的性质是**每一次运用都是一次潜在的质疑**：成功则无误（只需记一笔），
任何失败或不匹配都会使 agent 怀疑经验本身。这要求格式支持
**单次运用的 O(1) 回写**。

| 形态 | 一次运用后的回写代价 |
|---|---|
| 小模型 | 重训 / 适配器更新——高，且是聚合的 |
| RAG 知识库 | 重建索引——中，且是聚合的 |
| 段 | 通过量 +1；仅在需要时收窄适用域——**O(1)** |

**C41｜“成功 = 计数器；失败 = 语义修订候选”这条不对称，
正是 C20–C23 的三分规则。** 段是唯一同时满足“O(1) 回写”与
“失败可回灌语义”的形态。

## 四、内存灾难的正确回答：分层承担（C42）

不必追求“整体不增长”；不同层承担不同规模，且**每层存的东西不同**：

| 层 | 规模 | 存什么 |
|---|---|---|
| 厂商（先天 / 预设） | 几十 ~ 几千 | **参数化模板 + 判据族**（随模型版本回归，见 C9） |
| 用户（后增） | 几十 ~ 几百 | 实例化后的段（图） |
| 跨用户聚合（若建） | 百万级 | **统计量，不是段** |

**C42｜三条判断：**

1. **用户不需要处理那么多经验。** 保留集与“重复工作量”同阶，而不是与“总工作量”同阶
   （通过量门限，见 U3）。
2. **先天经验没有必要做非常多，多了有害。** 它的质量指标是**压缩比**
   （覆盖的变体数 / 段数），不是段数。厂商侧真正要维护的是
   **少量高抽象模板 + 一套判据族**；具体实例化由用户环境完成。
   段数一多，识别成本与判别式的脆性同时上升。
   这与 `scale-index-design.md` §6.1 “经验天然聚集在少数能力族”是同一个事实。
3. **“百万级”是“跨层聚合且未去重”才会出现的数字。**
   在段图 + 通过量门限下，没有任何一层需要原样持有它；
   聚合层要的是统计量（哪些模板被穿过得多），不是段本体。
