# 13 · 有/无 experience 的配对对照（第一轮）

> 2026-09-17。脚本 `active_leg/compare.py`，原始数据 `active_leg/out/compare.jsonl`。
> 设计：**同一模型、同一 agent、同一份显式规格**，只在"有没有经验工具"上分叉；
> 4 个低关联任务，每任务一对；两臂都给 `approvalPolicy=never` /
> `sandbox=danger-full-access`，保证基线臂能用内建工具。
>
> 关键设计约束：**规格在两臂完全相同**——有经验的一臂拿到的不是更多信息，
> 只是少做操作。否则测的是"谁被告知得更多"，不是"谁做得更少"。

## 二、诚实判读：方向对，但**还不能称其为证明**

**先说好的**：

- **4/4 全部正确**，没有拿速度换正确性；
- **经验在 4/4 都被调用**（不是靠 prompt 诱导）；
- **主指标方向一致**：3/4 任务的 `model_requests` 少了 1–2 次，wall 也快；
- 少的是**模型往返**，不是 token —— 这正是我们要主张的东西。

**再说不足，这些不能被忽略**：

1. **n=4 对，符号检验 p≈0.31，不显著。** 3/4 与 4/4 之间的差别就是"没有结论"；
2. **有一个任务反向**（docs_index：慢 6.1s、多 1 次请求）。n=1/格，无法判断它是
   真实反例还是我们刚刚在 §12 学到的那个长尾噪声；
3. **省略幅度很小**：`model_requests` 从 4–6 降到 3–4。因为任务本身只有 2–5 个文件操作，
   而**模型至少需要"理解 → 行动 → 确认"三次往返**，经验只能省掉中间那部分。

## 三、真正重要的推论：效应量随**已知前缀长度**增长，不随任务数增长

这一轮测的是"很多个短任务"。而我们的主张是"**已知前缀不经过模型**"——
那么节省应当与**前缀里的操作数**成正比，与任务个数无关。

用 4–5 个操作的规格去测，天花板本来就只有 1–2 次往返。
要让效应量变得可见，规格应该是**20–50 个操作**的（真实的发布检查、模块迁移、
多文件配置生成），那时"模型自己逐个发工具调用"与"一次调用经验"的差距才会展开。

## 四、要成为"依仗"，还差什么

| 项 | 现在 | 需要 |
|---|---|---|
| 配对数 | 4 | **≥10** |
| 每格重复 | 1 | ≥2（吸收长尾） |
| 规格规模 | 2–5 个操作 | **20–50 个操作**（效应量所在处） |
| 主指标 | model_requests / wall | 保持，再加"**模型自己发起的工具调用中属于已知前缀的次数**" |
| 正确性 | 文件内容全等 | 保持（快而错不算省） |
| 判读 | 单轮 | 符号一致率 + 配对中位差，n≥10 后做符号检验 |

## 五、回答甲方的问题

> "我们能不能证明 experience 的价值？这是能不能去要求获取深度改造权限的重要依仗。"

**现在还不能证明，但已经拿到方向，并且知道了证明需要什么。**

具体地说：

- 我们证明了 **机制成立**：经验在官方 stock 二进制上被模型主动调用、真实执行、验证通过；
- 我们证明了 **方向存在**：4 个任务里 3 个在"模型往返次数"这个主指标上变少；
- 我们**没有**证明 **效应量足以支撑一次权限请求**：n=4、不显著、幅度小、且有 1 个反例。

差距不在路线，在**实验的规模**：配对太少、规格太短。
把这两个补上，要么拿到一条站得住的曲线，要么诚实地知道这条路线的上限——
两种情况都比现在这份"看起来不错但统计不足"的数据有用。
