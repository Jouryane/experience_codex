# 07 · experience 是 LLM 的时间维度

> 本条定义由甲方提出（2026-09-16）。本文件只留**定义与推论**。
> 对外沟通记录与宿主接口核对移到 [08](08-outreach-and-interfaces.md)，
> 价值判断移到 [03](03-host-value-argument.md) §六。
>
> **判断一个定义好不好的标准不是它漂亮，而是它消解的问题多、制造的问题少。**
> 这一条通过了这个检验：一次消解六条矛盾，只新增一条代价。

## 一、定义（C45）

**experience 不是 LLM 的竞争者，而是 LLM 的时间维度。**

experience 仍然可以被 LLM 主动调用，但更多的时候是
**“默默观测、弹射可用的经验”**。

为什么这个说法是准的：

- 在纯 API 视角下，LLM 是**时间不变**的——同样的输入给同样的分布。
  它唯一的“时间”是**上下文窗口里的叙事**，而那只是时间的记叙，不是时间本身。
- 所以每一轮它都在重新推导。不是因为它笨，是因为**它没有过去**。
- experience 提供的正是它缺的那一件：**在世界里已经发生过的、不必重读就能
  据以行动的事实**。

与既有结论的关系：C6 说“experience 是 agent 的属性”，本条是它的**加强**——
维度是一种结构性属性：去掉它，agent 不是少了个功能，而是**失去了拥有过去的能力**。
属性可以缺席，维度不能。

**也要说清比喻的边界**（三处不成立的地方）：

| 时间 | experience |
|---|---|
| 连续、无条件 | 离散、有条件 |
| 不会错 | **会错**（误识别） |
| 无人值守也无所谓 | 错在无人看管处代价更大（见第五节） |

所以更精确的说法是“**一个只在条件成立时走动的钟**”，不是“时间”。

## 二、推论一：默认形态是“被动弹射”，不是“拦截”（C46）

这条推论直接改掉了我们此前的默认。

| | 此前实现（lvl1 / 早期 lvl2 讨论） | 新定义要求 |
|---|---|---|
| 触发源 | 模型先提出动作 → 经验拦截 | **世界状态变化** → 前提成立 → 弹射 |
| 默认 | 只有主动调用路径 | **被动弹射是默认**，主动调用是次要形态 |
| 模型没提到它时 | 永不触发 | 该触发就触发 |

这不只是措辞。此前的隐含前提是“模型会提出那个动作”；一旦模型这次没提，
经验就沉默——**而那恰恰是它最该起作用的时候**。

“默默观测、弹射可用”的对照物是记忆：人不需要“记得去回忆”，记忆会自己浮上来，
主动回想是少数。**经验如果主要靠主动调用，它就是工具；主要靠被动弹射，它才是维度。**

## 三、推论二：N1 不是死结，是坐标轴选错了（C47）

我们此前把 N1 表述为“没有 LLM 之前的先动手座位”。重新看，这是一个
**分类学上的空缺，不是原则上的禁止**。

### 3.1 空的是什么

以 DSH 自己的分类为例：每个提示词策略、会话开始观察、工具前策略、
dispatch 前后控制、工具后变换、最终结果观察、带模型可见原因的续跑。

把这七项抽出来看，**它们全部由“agent 流的坐标”参数化**：某一步之前、某个工具
之前、某个工具之后、停止时。**没有任何一个由“世界状态的坐标”参数化**
（世界变了 → 某个已知转移该发生了）。缺的是后者。

### 3.2 死结只在“替模型思考”那一半

| 一半 | agent 架构会不会让 | 依据 |
|---|---|---|
| **替模型决定** | **不会让，也不该让** | 这是 agent 的第一性：决定权归模型 |
| **在模型之外把世界推进，并让模型看见** | **可优化空间** | 世界本来就有自己的时间线（用户改文件、cron、其它 agent 都在动） |

而且这条线**是我们自己已经画好的**。`step-gate.md` §3 原文：

> Experience **可以偷偷把世界往前推进**（真实 Environment 改变）；
> Experience **不能偷偷替 Agent 思考**（不注入决策、不控制规划）。

所以答案是：**N1 一半是死结、一半是纯优化空间，而分界线我们本来就清楚。**

### 3.3 换轴之后，座位其实已经有（本轮最反直觉的发现）

在“agent 流”的坐标里找座位永远找不到；换到“世界时间”的坐标，
DSH 已经有两个门口：

| 已有机制 | 原始描述 | 与“时间维度”的关系 |
|---|---|---|
| `ctx.jobs` | “Add background work — register on `ctx.jobs`; `job_*` tools collect or stop it” | **不由模型驱动的工作**；模型负责收集结果 |
| `ctx.schedule` | 独立包，监听 `agent/created` 等 | 按时间/事件触发的工作 |

也就是说：**“默默观测”不需要新座位，`ctx.jobs` 就是那个座位**；
“弹射”就是 job 产出、模型收集。真正缺的只剩两件小东西：

1. 一个**已验证转移的运行器**（把“前提成立 → 执行 → 验证后置”跑起来）；
2. 一条**带来源的自产事实进上下文**的路径（让模型看见这次弹射真的发生过）。

### 3.4 于是 N1 分解成两个能谈的小问题

- **Q-a**：既有机制（`ctx.jobs` / 插件的后台工作）能否承载“由世界状态触发、
  而非由模型触发”的已验证转移？
- **Q-b**：一次弹射产生的**自产事实**，能否以可信来源进入模型的下一次上下文？

两个问题都不要求宿主放弃任何不变量。

## 四、推论三：新定义把 N2–N7 全部降级（C48）

**新定义让每一条都从“麻烦”变成“非问题或特性”。**

| # | 新定义下 |
|---|---|
| N2 | 只在**主动调用 / 拦截**模式下存在（那时确实要冒充工具）；**被动弹射模式下不存在**，因为它不冒充任何工具，它就是一条事实 |
| N3 | 从“代价”升级为“**定义的一部分**”：弹射是一次可重建的事实，这正是“时间维度”的含义。会话格式升版不是税，是特性落地 |
| N4 | 超时继承是“把预算挂在工具上”的后果；换到 job / 独立响应通道的坐标，预算属于它自己的生命周期 |
| N5 | 注入会被 compaction 吃掉，是因为它是“上下文”；**弹射的记录是 durable 事件，不是可被压缩的上下文** |
| N6 | 监听者顺序：拿出顺序保证属 API / 协作问题，不是设计冲突 |
| N7 | 惩罚只发生在我们试图把经验塞进“agent 流”的座位时；弹射作为**独立事实类型**不但不违反 “model-visible means logged”，反而**满足**它 |

完整重评（含注册模式的影响）见 [05 §四](05-dsh-integration-map.md)。

## 五、新定义要我们付出的代价（诚实那一面）

**一条钟如果走错，没有人在看。**

拦截模式下，动作是模型提出的，天然有一次检查；弹射模式下没有任何检查点。
所以实验里那些“好用的缓解手段”在弹射模式下全部变成**强制项**：

| 实验得到的机制 | 在拦截模式下 | 在弹射模式下 |
|---|---|---|
| 三值门控（`UNKNOWN` 不放行） | 有用 | **强制** |
| 前提必须被自身动作证伪（C44） | 发现才修 | **强制**——否则钟会一直响 |
| 通过量门限 | 省空间 | **强制**——它是“没有重复就没有经验”的唯一保证 |
| 备份与回滚 | 保险 | **强制**——无人看管时这是唯一的退路 |
| 弹射必须留痕 | 顺带 | **强制**——否则模型永远不知道自己被改过环境 |

即：**E4–E9 从“不错的实验结果”升格为“载重要求”。**
