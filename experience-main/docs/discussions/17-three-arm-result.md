# 17 · 三臂对照：谁来决定用不用经验

> 2026-09-18。脚本 `active_leg/prefetch.py`，数据 `active_leg/out/prefetch.jsonl`。
>
> - `off`：全任务交给模型
> - `pull`：全任务 + 模型**可以自己选**的动态工具（13–15 测的就是这个）
> - `pre`：**客户端先匹配并执行已知前缀**，再把剩余部分交给模型
>
> 甲方的比喻定了设计：抬腿不需要上位机算角度。**匹配与执行不该由模型决定。**

## 一、数据（9 轮全部 `correct=True`）

| 任务 | 经验覆盖整任务 | 臂 | 模型轮次 | model_requests | wall_s | 经验调用 |
|---|---|---|---|---|---|---|
| scaffold_full | 是 | off | 1 | 6 | 21.7 | 0 |
| scaffold_full | 是 | **pull** | 1 | **3** | 5.9 | 1 |
| scaffold_full | 是 | **pre** | **0** | **0** | **0.0** | — |
| repair_full | 是 | off | 1 | 6 | 17.5 | 0 |
| repair_full | 是 | **pull** | 1 | **5** | 16.5 | 1 |
| repair_full | 是 | **pre** | **0** | **0** | **0.2** | — |
| repair_plus_note | 否 | off | 1 | 7 | 18.1 | 0 |
| repair_plus_note | 否 | pull | 1 | 9 | 28.0 | 1 |
| repair_plus_note | 否 | **pre** | 1 | **14** | **45.8** | 0 |

## 二、尺子已修好（round 16 的撤回已解决）

两个独立计数器在 7 个模型轮次里**完全一致**：

```
tokenUsage 通知数 == usage 记录数    （6=6, 3=3, 6=6, 5=5, 7=7, 9=9, 14=14）
```

所以 `model_requests` 现在可以作为结论依据。

## 三、决定性的结果：`pre` 覆盖整任务时，模型轮次为 **0**

```
scaffold_full / pre : 模型轮次 0，requests 0，wall 0.0s，correct True
repair_full   / pre : 模型轮次 0，requests 0，wall 0.2s，correct True
```

**这个 0 是构造性的，不依赖任何计数器**：`pre` 臂根本没有调用 `turn/start`，
客户端自己匹配、执行、用判据验证，任务就完成了。对比基线 21.7s / 17.5s。

这就是「已知前缀不经过模型」的第一个**不需要统计学**的证据。
它也解释了 13–15 为什么打不出来：那三轮把决定权交给了模型，
于是模型必须先花一次探索去确认"该不该用"，成本与自己做一遍相当
（见 [16](16-why-known-path-is-expensive.md) §二）。

## 四、同时暴露了一个新的、明确的负面结果

**部分覆盖（`pre` + 只做了一部分）反而更差：14 次请求 / 45.8s，对比基线 7 次 / 18.1s。**

给模型的消息是"与目标值相关的修复已经完成并由自检验证通过，你只需完成其余要求"。
模型的反应显然是**不信**：它重新验证了已完成的部分，再去做剩下的。

**结论：交接必须携带它无法反驳的证据，而不是一句声明。**
这与 round 11 那条发现是同一类错误（给更多信息 ≠ 更快收敛，但**给一句无证据的声明
会触发反向核查**）。

## 五、`pull` 这一臂的表现不稳定，不能当结论

本轮 `scaffold_full` 的 pull 是 3 对 6（好），但 13–15 三轮是 0/9。
两处的差别只在经验数量与任务措辞。**n=1，且与前三轮矛盾，不作为结论使用。**
它只说明一件事：pull 的表现对设置高度敏感，不是一个可靠的机制。

## 六、当前可信的结论（按强度排）

1. **构造性成立**：客户端在模型之前执行已知前缀时，覆盖整任务则**零模型调用**，
   且结果通过判据验证。这是 pull 模式下做不到的。
2. **部分覆盖目前是负收益**：无证据的"已完成"声明会让模型重新核查。
3. **pull 不可靠**：对设置敏感，四轮里三轮为零。
4. **未验证**：跨会话重复（定向成本摊薄）仍未测。

## 七、同日复跑：§四 的"部分覆盖更差"不成立

2026-09-18 同配置复跑 `repair_plus_note`（同样是 n=1）：

| 臂 | model_requests | wall_s | correct |
|---|---|---|---|
| off | 7 | 18.5 | True |
| pre（带声明） | **5** | 18.4 | True |
| pre（**不带声明**，`pre_silent`） | **11** | 51.9 | True |

两个结论都要修正：

1. **§四 的"部分覆盖更差"撤回。** 同一个 `pre` 臂从 14 次掉到 5 次——
   同配置摆动 2.8 倍，与 §五 说的"高方差"是同一个现象。
   **§四 当时把一次长尾当成了效应。**
2. **"不宣告会更好"这个预测被证伪。** 不带声明反而更贵（11 vs 5）。
   问题二的机制解释因此仍然是**未验证的假说**，不能作为设计依据。

**这一节的存在本身是本项目最重要的一条方法学结论**：
在这个度量上，**任何 n=1 的方向性结论——包括我给出的——都必须先当作噪声处理。**
