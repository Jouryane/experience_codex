# Experience：让 Agent 的经验变得可复用、可审计、可回滚

> 这份文档面向使用者与协作者，回答四个问题：**它是什么、怎么用、用在哪些场景、
> 边界在哪里**。文中每一条能力都在仓库里有对应实现与验收（见文末索引）。

## 0. 一句话

**Experience 不试图让 Agent 更聪明，而是让“已知且可验证的部分”变得更快、更稳、
可审计、可回滚**；剩下的判断永远留给模型和人。

它把 Codex / Trae / Claude Code / DeepSeek harness 等当作可插拔执行器：
已知部分由 Experience 直接完成（先动手），无法确定的部分再委派给 Agent；
每次真实执行都会沉淀为**经验候选**，经资格验证后成为可复用能力。

核心原则：**不伪造状态、失败即停、先动手后委派、用户保有决策权。**

## 1. 使用方案：三个阶段

### 阶段 1｜接线（一次性，约 10 分钟）

- 启动：双击 `Experience.exe`（薄启动器 + 本地 server + 浏览器 UI）；
- 在「助手」页注册 executor：指向 Codex 的 `directory` 或 `executable`；
  `channel=session` 走真实会话，`exec` 走一次性命令；
- 在「设置」页定三件事：能力策略（写=仅工作区、删除默认关、命令执行默认关）、
  学习开关（LLM 编译器）、撤销保留数。

### 阶段 2｜日常（核心循环）

1. 在「任务」页提交任务（assistant + 工作目录 + 可选场景）；
2. L3 入口按场景唤醒 ACTIVE 经验 → **可验证的部分进程内直接做完**（自动备份）；
3. 剩余部分带「已完成步骤 + 已验证状态」委派给 Codex；
4. 会话结束 → L1 把这一轮真实轨迹蒸馏为**候选经验**（默认不激活）。

### 阶段 3｜治理（低频，但决定长期效果）

- 候选 → 五级验证门 → VALIDATED → ACTIVE；
- 在经验库用树/详情/审计/评分/别名/偏好管理，用「同族经验」看重复；
- 需要时按快照一键撤销（设置页「撤销最近的经验执行」）。

## 2. 业务流程（任务视角）

```text
提交任务
 ├─ 1 场景过滤：scope 不匹配 → 不进候选
 ├─ 2 工具面：trigger.tool 不等 → 跳过
 ├─ 3 文本面：command_pattern 命中（当前为子串匹配，可替换）
 ├─ 4 前提面：precondition 必须可观测且成立（Unknown ≠ 成立）
 ├─ 5 闸门：Gate 3 可观测 / Gate 4 dry-run / Gate 5 结论可观测
 ├─ 6 唯一最优：多个候选取覆盖最大；平局 → 拒绝自动执行（转委派）
 └─ 执行：策略校验 → 工作区围栏 → 备份 → 执行 → 判据 → 回写 usage/confidence
        └─ 之后仍委派（原任务 + 已完成状态 + 回滚指令）
```

**关键细节**：命中经验不是“给提示词”，而是**执行预编译的步骤**；
执行完仍要过判据，`success / misfire / invalid` 分层回写，失败能区分
“前提不成立（不扣分）”与“环境出错”。

## 3. 经验如何被使用 / 没有匹配会怎样

**被使用时**：经验是预编译执行体——文件写入/追加/复制/移动/删除、
受控命令执行（白名单 + 超时 + 输出上限 + 证据）。判据来自注册表：
`file.exists/content/size/sha256`、`dir.exists`、`process.exit_code/stdout_contains`、
`git.dirty/branch/last_commit`、`http.status/body_sha256`、`port.open`。

**没有匹配时**，三种回退都不阻塞：

| 情况 | 行为 |
|---|---|
| 无任何 ACTIVE 经验 | 纯委派，任务完整交给 executor（v1 语义，不发 delegate 事件） |
| 有 ACTIVE 但未命中 | 委派并附 plan context（已知经验清单，仅供参考，不注入指令） |
| 只有参考经验且注入开启 | 以“参考、可质疑”的上下文注入，agent 主导 |

---

## 4. 用上 Experience 之后，Codex 还能正常用吗？

能，且这是设计前提。Experience 是**前置编排层**：

- Codex 仍是完整执行器（`session` 通道走它自己的 app-server，`exec` 通道走
  `codex exec`）；
- 密钥、审批、沙箱由 Codex 自己管理，Experience 不读取密钥；
- Experience 只做三件不侵入的事：给任务补一段“已完成部分”的事实说明、
  拦截**它自己范围内**的步骤、记录轨迹用于学习。

可以只用 Codex，也可以混搭多个不同 Agent。

---

## 5. 好处（都可验证，不是口号）

- **省 token、省时间**：机械段在进程内完成，模型只处理判断部分；
- **可审计**：每一步进 ledger（执行 / 委派 / 回滚 / 设置变更）；
- **可回滚**：写操作前自动备份，按快照一键恢复；
- **不越权**：默认只允许工作区写入，删除与命令执行默认关闭，
  越界与危险动作在**副作用之前**被拒；
- **越用越准**：使用次数/衰减/置顶/用户偏好形成个性化排序，且不改证据。

## 6. 自定义：适合哪些场景、如何调整

### 6.1 最适合经验化的场景

高频、机械、结果可判定：脚手架与配置生成、仓库例行检查、构建与测试、
服务就绪探测、大文件完整性校验。

### 6.2 两个可调的“旋钮”

| 方向 | 怎么调 |
|---|---|
| 更自动 | 开启命令执行白名单、显式授权删除、给读取上限加特殊许可、把经验置顶/提升为 ACTIVE |
| 更保守 | 把可疑经验设为停用、把命中降级为“仅参考”、收紧场景或策略、关闭学习 |

### 6.3 用户能改什么（权力边界）

- **可改**：显示名/别名、状态意图、个人评分、使用偏好、场景归属、草稿内容、
  能力策略与开关、撤销；
- **不可改**：证据与置信度的来源（那是系统事实，不是主观项）。

---

## 7. 硬伤：必须诚实说明

1. **语义匹配是子串**：`skip creating probe file` 会命中 `create probe file`；
2. **冷启动**：新装没有 ACTIVE 经验，价值随使用累积；
3. **蒸馏上限**：确定性蒸馏只接 `exec_command` 且需参数摘要，脏轨迹需要
   LLM 编译器（有成本）；
4. **判据面不完整**：不能观测的结论一律拒绝执行——这是诚实，也意味着
   “能自动的活比想象中少”；
5. **单机单用户**：并发多会话 + 单文件存储是已知边界；
6. **模型间差异**：同一任务在不同 Agent 上表现不同，委派文本无法完全约束；
7. **本质限制**：它只负责“可判定、可界定、可归因”的工作，判断类工作
   它做不了，也不该做。

我们把上述每一条都标注为**可替换的扩展点**，并给出升级路径
（见 `docs/learning-reuse-contract.md`、`docs/scale-index-design.md`）。

---

## 8. 显著提升生产力的六个方向

1. **仓库例行化**：提交前/发版前检查做成经验（git + 构建 + 测试退出码）；
2. **脚手架与迁移**：多文件改写一键到位并可回滚，团队共享同一套经验；
3. **服务与接口巡检**：`port.open` + `http.status` + `body_sha256` 组合成冒烟经验；
4. **半自动协作**：经验搭骨架、Agent 填内容，把最贵的判断时间留给模型；
5. **多 Agent 吸收**：把别的 Agent 的 run-notes 吸收为参考层，团队把
   “谁做得好”变成可复用资产；
6. **规模化的下一步**：先只读同族聚类，再按需加 `scope→tool` 倒排（1 万级）
   或词元/向量粗召回（100 万级）。

## 9. 行业场景一：金融 AI Agent

金融工作流的形状恰好是 Experience 的强项：**规则密集、步骤固定、
结果必须可验证且可审计**。

### 9.1 合规与开户类流程

投资适当性检查、KYC 材料齐备性、合同必备条款核对，本质是“一组确定性判据”
（文件字段、哈希、条款存在性、版本号）。

- 进程内完成并留痕，模型只处理边界情况；
- 版本用哈希锁定，防止“用错模板”；
- 出错一键回滚；
- **监管审计所需的“谁在何时改了什么”，正好是 ledger + 备份清单已经产出的东西**。

### 9.2 回归与回测流水线

回测/因子验证是“命令 + 退出码 + 指标输出”的典型任务：
受控命令白名单执行，`process.exit_code` 与 `stdout_contains` 作判据，
参数与结果哈希一并留档。**可复现性从“靠人自觉”变成结构性保证。**

### 9.3 数据对账与报表准备

每日 T-1 对账、异常清单生成、监管报表骨架填充：高频、机械、判据客观
（条数、总额、差额阈值）——这类活占分析师大量时间，也最适合被经验吸收。

### 9.4 与“让模型全权处理”的差别

| 维度 | 通用 Agent | Agent + Experience |
|---|---|---|
| 可复现性 | 每次重新推理 | 同一套步骤、同一组参数 |
| 可审计性 | 只有对话记录 | 执行/委派/回滚/设置全留痕 |
| 越权风险 | 依赖提示词约束 | 策略在副作用前拒绝 |
| 成本 | 每轮全量推理 | 机械段不进模型 |
| 失败归因 | “就是没做对” | 前提不成立 / 环境出错 分层 |

### 9.5 红线

下单、划款、密钥与凭证操作、对外发布**不交给 Experience 自动执行**；
外部接口只做只读观测且需显式授权。
**Experience 负责把可验证的合规与例行工作做扎实，不负责投资判断。**

## 10. 行业场景二：具身智能

具身场景的分工是：**模型管感知与决策，Experience 管可复现的技能模板。**

### 10.1 标定与启动例程

开机自检/标定：关节零位、力传感器基线、相机内参、工作空间边界检查。
固定顺序 + 明确阈值，适合经验化；判据来自注册表，**前置条件不满足就不动作**。

### 10.2 装配/抓取流程模板

接近速度、闭合力阈值、抬起高度、超时等参数做成“技能卡”：
执行前核对工件在位、工具已装夹；执行后核对力曲线峰值与位置误差容差。
模型只在换工件/换工位时介入判断。

### 10.3 故障恢复剧本

卡料、抓取失败、通信超时是最耗时也最该自动化的部分。
“退让 → 重夹 → 重试 N 次 → 仍失败则停机并保留现场”这类剧本，
用经验表达比用提示词可靠得多，且每次执行都留证据便于复盘。

### 10.4 与上位机操作的关系

HMI、标注软件、仿真器的操作走预留的 Computer Use 适配器契约：
**语义选择器优先、每步证据、不可逆动作需确认、默认拒绝**。
在具身场景中，坐标与像素差不可作为唯一判据——这一点尤其重要。

### 10.5 需要的扩展

现有判据族（文件/进程/仓库/接口/端口）需扩到 `state.*`（关节角、速度、力）、
`sensor.*`（基线/读数）、`episode.success`、`safety.estop`；
执行侧从“命令”换成“动作通道”，但顺序不变：
**策略校验 → 边界检查 → 快照 → 执行 → 判据**。

## 11. 两个场景的共同结论

| 维度 | 金融 AI Agent | 具身智能 |
|---|---|---|
| 经验吸收什么 | 合规检查、回测回归、对账、报表骨架 | 标定例程、技能参数、故障恢复剧本 |
| 判据来源 | 文件哈希/字段、退出码、只读接口 | 状态量、力/位置容差、回合结果 |
| 不交给经验 | 下单、划款、密钥、对外发布 | 感知、规划、人类安全决策 |
| 最强价值 | 可复现 + 可审计（监管级留痕） | 可复现 + 可回滚（现场可复盘） |
| 需要的扩展 | 更细的只读接口判据与策略分级 | 状态/传感器谓词族 + 动作通道 |

一句话：**在高风险领域，Experience 不追求更聪明，而是把“已经验证过的做法”
固化成带证据、可回滚、受策略约束的执行体**——这恰好是金融与具身最缺、
也最贵的那一层。
